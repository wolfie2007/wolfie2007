# Setup

## 1. Create the special profile repo
Create a new **public** repo on GitHub named exactly `wolfie2007` (same as your
username) — GitHub auto-detects this and shows its README on your profile page.
Push everything in this folder to it as `main`.

## 2. Create a Personal Access Token (for live stats)
`streak.svg`, `langs.svg`, `year.svg`, and `stats.svg` are generated by a
scheduled GitHub Action that queries the GraphQL API for your contribution
calendar and language usage. The default `GITHUB_TOKEN` Actions gives a
workflow can't read that data — you need a PAT:

1. GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens (or classic, whichever you prefer).
2. Scopes needed: `read:user` (classic) — or for fine-grained, grant
   **read-only** access to your account's "Followers" isn't needed; just
   `read:user` / public repo metadata is enough since we only read
   contribution + public repo language data.
3. Copy the token.
4. In the `wolfie2007/wolfie2007` repo → Settings → Secrets and variables →
   Actions → New repository secret → name it `GH_PAT`, paste the token.

## 3. Run it once manually
Repo → Actions tab → "Update profile stats" → Run workflow. Check that
`streak.svg`, `langs.svg`, `year.svg`, `stats.svg` get committed with real
numbers. After that it runs automatically every day at 03:00 UTC.

## 4. Regenerating the portrait or headings (only needed if you change photo/text)
These are NOT part of the daily Action — they're static assets you generate
once locally and commit:

```bash
cd scripts
pip install fonttools brotli Pillow
python3 generate_ascii.py /path/to/photo.jpg ../ascii.svg 100
python3 generate_headings.py
```

`fonts_src/` holds the JetBrains Mono TTFs those two scripts subset from —
already included, no need to redownload unless you want a different weight.

## 5. Local test of the live stats scripts (optional)
```bash
cd scripts
GH_PAT=ghp_xxx PROFILE_LOGIN=wolfie2007 node build.mjs
```
This writes streak.svg / langs.svg / year.svg / stats.svg straight into the
repo root, same as the Action does.
